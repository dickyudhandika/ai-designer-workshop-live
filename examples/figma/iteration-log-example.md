# Iteration Log

**Example output.** Five iterations on the photo marketplace homepage, built from `assets/DESIGN.md` against the Unsplash reference picked in Phase 1. These are real evaluation notes — every entry names a specific defect and the specific fix. Nothing says "looks good."

Format reference: `session-1/iteration-log-template.md`

---

## Iteration 1 — Structure + Layout
**Screenshot:** `output/figma/iteration-1.png`
**What was built:** Page frame 1440×2400. Top nav (72px): wordmark left, full-width search input centre, "Log in" right. Category chip row (120px) with 8 `muted` tiles at 160×120, gap `md`. Photo grid: `repeat(auto-fill, minmax(280px, 1fr))`, 4 columns at this width, gap `lg` (16px), 12 cards as `#F3F1EB` rectangles with "IMAGE PLACEHOLDER" text. Featured collection band (3 cards, full width). Footer (180px) with email input and link columns.
**Evaluation:** Skeleton is right — nav, chips, grid, collection, footer all present, and the grid starts at ~208px from the top of the page with no marketing band above it. That matches the Unsplash reference read. Three defects: (1) the search input is only 480px wide and sits left-of-centre, so it's outranked visually by the wordmark — in the reference search is unambiguously the widest element; (2) chips are 120px tall and read as boxes, not labels; (3) all 12 grid cards render at identical 280×210 crop, which is uniform-grid behaviour and contradicts the reference read.
**Changes for next iteration:** Search to `flex: 1` with `margin-inline: 2xl` — target ~720px at this width. Chip height 120px → 40px with `label-sm` text, and keep one 160×120 image tile as the *category thumbnail* pattern only (not the chip pattern). Set three grid cards to span 2 rows and two to span 2 columns so the grid has deliberate variation rather than accidental repetition.

## Iteration 2 — Token Application
**Screenshot:** `output/figma/iteration-2.png`
**What changed:** Bound all fills to variables via `set_bound_variable` — page `background` `#FDFCF8`, nav and footer `background`, chips `muted` `#F3F1EB`, chip text `foreground` `#1A1A1A`, card titles `foreground`, photographer names `muted-foreground` `#A1A1A1`, all separators `border` `#E5E2D9`. Applied text styles: wordmark `title-h4` (32px Fauna One), card titles `label-md`, photographer `label-xs`, prices `label-sm`, footer headings `label-xs` uppercase. Search input padding `md lg` (12px 16px), radius 0px. Hero-adjacent spacing audited to the 4px scale.
**Evaluation:** Token compliance is close to complete — a fill audit shows zero raw hex values in the tree. Two real defects: (1) the "Log in" button is `primary` blue `#1A5EFF` *and* the search submit is `primary` blue, so there are two `primary` elements above the fold — that violates the one-primary-per-screen rule, and worse, the account utility action is outranking the product's actual task; (2) every grid card has a 1px `border` `#E5E2D9` wrapping the image placeholder. Border around a photo is decoration, not separation — the photo is its own boundary.
**Changes for next iteration:** "Log in" → `ghost` variant (transparent, `foreground` text, border on hover). Search submit becomes the single `primary`. Remove the border node from `PhotoCard.Root` — replace with `photo-backdrop` `#EDEAE1` fill on the image frame so a non-matching aspect ratio still reads as intentional. Verify no card has both border and shadow (the baseline forbids the combination; currently they have border only, so removal is a pure subtraction).

## Iteration 3 — Content Refinement
**Screenshot:** `output/figma/iteration-3.png`
**What changed:** Replaced all placeholder copy with real content. Search placeholder: "Search free photos — nature, people, architecture". 8 chips renamed to real categories: Trending, Nature, People, Business, Food, Architecture, Travel, Wallpapers. 12 grid cards given title + photographer + price — e.g. "Misty pine forest at dawn" / "Elena Vasquez" / "$12"; "Concrete stairwell, oblique light" / "Marcus Oyelaran" / "$8". Featured collection band retitled "Curated — Fog & Concrete" with three cards sharing a slate/green/fog-white palette. Footer: email capture with real label, four link columns, copyright line with the current year.
**Evaluation:** The page now reads as a marketplace rather than a wireframe — grid cards pass the "does this look like inventory" test and the featured band genuinely reads as curated because the three card titles share a subject family. Two defects: (1) four of twelve grid cards are nature landscapes, so the grid reads as a nature marketplace; the reference (Unsplash) is deliberately broad and the categories above it promise breadth; (2) the featured collection's three cards have metadata rows at different heights because one title wraps to two lines, which breaks the row baseline and makes the band look sloppy.
**Changes for next iteration:** Rebalance grid subjects — keep 2 nature, add 2 architecture, 2 people-at-work, 2 food, 2 business/office, 1 travel, 1 abstract. Trim card titles to a hard 42-character limit and set `text-overflow: ellipsis` on `PhotoCard.Title`; verify all three collection cards share a baseline. Add a `LicenceBadge` (default variant) to the bottom-left of three grid images, `xs` (4px) inset.

## Iteration 4 — Visual Polish
**Screenshot:** `output/figma/iteration-4.png`
**What changed:** Added `shadow.subtle` (0 1px 2px, 4% opacity) to the footer only — the one surface that genuinely sits above the page flow. Chip hover set to `border` fill with `duration.fast` (150ms) `ease-out` on background-color. Grid images given `photo-backdrop` behind them where the natural ratio leaves remainder. `LicenceBadge` placed on three cards. Featured band given `3xl` (48px) section gap above and below so it reads as a chapter. Nav set to 72px with `border` hairline beneath.
**Evaluation:** The polish pass landed mostly well — the chip hover is correct and fast, the `3xl` gaps separate the collection band properly, and the licence badges add real buyer information without noise. But two additions went too far: (1) `shadow.subtle` was also applied to the nav bar, and the nav is not elevated — it's flush with the grid, so the shadow is decoration and the baseline forbids it; (2) the licence badges are `primary`-variant (blue fill), which is the reserved active/positive state — on a metadata object it reads as a status alert and adds a second blue surface above the fold.
**Changes for next iteration:** Remove the shadow from the nav — hairline `border` beneath is sufficient separation. Change `LicenceBadge` to the `default` variant (`muted` fill, `border` outline). Screenshot the full page at 1440×2400 and diff against the Unsplash reference above-the-fold crop.

## Iteration 5 — Final Review
**Screenshot:** `output/figma/iteration-5.png`
**What changed:** Removed nav shadow and replaced with `border` hairline. `LicenceBadge` → `default` variant. Ran the full pre-flight checklist; fixed the last two failures — one stray `12px` gap in the chip row (not on the 4px grid; corrected to `md`), and the footer email input using `border` colour for its placeholder text (corrected to `muted-foreground`, which passes AA).
**Evaluation:** Above the fold now matches the reference read: nav, search, chips, first grid row — nothing else. One `primary` element on screen (search submit). Zero raw hex in the tree; all fills bound to variables. Grid is masonry with deliberate spans, not uniform. Cards carry no border and no shadow, metadata sits below the image with no overlay. The featured band reads as a distinct curated chapter. **Gaps remaining, named honestly:** (1) the homepage has no empty-state or zero-results treatment — the reference doesn't either, but it's the unclaimed position identified in the competitor analysis and it's still not built; (2) licences are only badged on 3 of 12 cards, so the treatment is inconsistent — either badge all paid cards or none; (3) mobile breakpoint (< 768px) is unbuilt — the grid needs a 2-column fallback and the chips need horizontal scroll.
**Changes for next iteration:** Session 2 territory — replace the 12 grid placeholders with generated images using `output/images/prompts.md`, then re-evaluate whether the card metadata baseline holds once real images with varying natural ratios are in place. Deferred: mobile breakpoint, zero-results state, licence badge consistency.
